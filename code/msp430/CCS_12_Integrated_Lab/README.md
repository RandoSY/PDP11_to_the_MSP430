# Integrated sensor evidence and supervisor — candidate

This additional CCS project supports Chapter 10's evidence capture and Chapter 11's control exercise. Import this folder and build Debug. It has built with CCS 20.4.1 / TI compiler 21.6.1.LTS, but is **not physically verified**. Before connecting the sensor, validate reset, presence, read and write slots on a scope or logic analyzer; connect exactly one externally powered DS18B20, P1.7 data with a verified pull-up to 3.3 V, and common ground. Never use mains or a real actuator.

P1.0 is the cooling-request indicator and P1.6 is the fault indicator; confirm actual G2ET LED polarity and jumpers. P1.6 cannot simultaneously be the 1 kHz timer output. UART TX is P1.2, 9600 baud, 8N1, 3.3 V; confirm LaunchPad UART jumpers. Disconnecting the host receiver should not affect USCI transmit-ready or local control, but this is an experiment to verify, not an observed result.

Capture each complete serial line with a host timestamp and retain it with board/sensor identity, externally supplied power, the pull-up, clock calibration, firmware hash, compiler settings, instrument and thermometer observations. Format: `SEQ_HEX=hhhh,STATUS=n,STATE=n,X16_HEX=hhhh,ROM=...,SCRATCH=...,INJECT=n`. ROM is eight bytes in wire order, scratchpad nine bytes in wire order, or `NA` when no bytes were captured. The scratchpad configuration is byte 4; its resolution and actual external power mode must be recorded from the setup. `X16_HEX` is a signed two's-complement 16-bit Celsius value in sixteenths, and is meaningful only when status is 0. Sequence is a 16-bit counter and wraps; it is not a timestamp.

Status: 0 decoded, -1 no presence, -2 scratch CRC error, -3 invalid argument, -4 ROM CRC error, -5 wrong family, -6 deliberately simulated stale data. The single-device Read ROM command and valid ROM CRC do not establish that the bus has only one device; that is a wiring assumption. The nominal 750 ms delay assumes 1 MHz and external power. It does not measure conversion completion or temperature accuracy; review the power-on 85 C pattern and compare against an independent reference.

For fault tests, pause the debugger, set `inject_fault` to 1 to corrupt the captured scratchpad CRC, or 2 to simulate a stale sample without acquisition; resume and observe status, state 2 and the LED output. Set it back to 0 to resume normal attempts. State values are OFF=0, ON=1, FAULT=2. Output is set before serial reporting. Serial disconnect alone does not inject a fault. Actual disconnect, stale data, LED response and UART independence require physical tests. This is a blocking educational loop, with no watchdog, bounded acquisition timeout or independent real-time stale detection: an indefinite firmware stall can leave an earlier output state. It is not fail-safe or suitable for industrial control.
